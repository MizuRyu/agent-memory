# 検索精度改善とエージェント記憶の最新動向

## 現在の agent-memory の構成（ベースライン）

| 要素 | 実装 |
|------|------|
| キーワード検索 | FTS5 trigram |
| ベクトル検索 | sqlite-vec + Ruri v3 (768dim) |
| フュージョン | RRF (k=60) |
| スコア調整 | 時間減衰 (半減期30日) + プロジェクト重み (1.0 / 0.3) |
| チャンキング | Q&Aターン単位、ルールベース |
| メモリ管理 | 追記のみ（編集・削除なし） |

## 1. ハイブリッド検索の改善

### 1-1. RRF を超えるフュージョン手法

**Convex Combination（凸結合）**
`score = α × sparse_score + (1-α) × dense_score` で重み付け。ACM TOISの分析では、少量のチューニングデータがあればRRFを全テストデータセットのNDCGで上回る[論文](https://dl.acm.org/doi/10.1145/3596512)。ゼロショット環境ではRRFが依然有効。

**Dynamic Weighted RRF**
クエリの特性（平均tf-idf等）に基づいてキーワード/ベクトルの重みを動的に調整。ハルシネーション率の大幅低減が報告されている[解説](https://research.aimultiple.com/hybrid-rag/)。

→ **agent-memory への適用**: 現行RRFは良い出発点。改善するなら凸結合（パラメータ1つ追加）が最もコスパが高い。

### 1-2. Cross-Encoder Reranking

RRF後の上位候補をcross-encoderで再ランク。ハイブリッド検索のNDCGをさらに10-15%向上させられる。

日本語対応モデル:
- `hotchpotch/japanese-reranker-cross-encoder-small-v1` — 軽量な日本語特化[HuggingFace](https://huggingface.co/hotchpotch/japanese-reranker-cross-encoder-large-v1)
- `jinaai/jina-reranker-v2-base-multilingual` — 100言語対応、高速[HuggingFace](https://huggingface.co/jinaai/jina-reranker-v2-base-multilingual)

→ **agent-memory への適用**: RRF後に上位30件をcross-encoderでリランクする2段階方式。SQLite上で候補取得→Pythonレイヤーでリランク。**最もROIが高い改善**。

### 1-3. SPLADE（学習済みスパース検索）

BM25/trigramの代替として、学習済みスパースベクトルで検索。専門用語に強い[Pinecone解説](https://www.pinecone.io/learn/splade/)。ただしSQLiteネイティブ実装はなく、外部パイプラインが必要。

→ **agent-memory への適用**: コスト高。FTS5 trigramで十分機能しているなら後回し。

## 2. チャンキング戦略の改善

### 2-1. Semantic Chunking

隣接文間のコサイン類似度が閾値以下の箇所で分割。単純手法よりrecallが最大9%向上[解説](https://www.firecrawl.dev/blog/best-chunking-strategies-rag)。

### 2-2. Parent-Child Chunking

- Child chunk (300トークン) をインデックスし、マッチ時にParent chunk (1,500トークン) をLLMに返す
- 「壊れたコンテキスト」によるハルシネーションを防止[Weaviate](https://weaviate.io/blog/chunking-strategies-for-rag)

### 2-3. エージェント会話への提案

現在のターン単位に加えて:
- **セマンティック境界でサブタスクグループ化** — 同一タスクの連続ターンをparent chunkとして束ねる
- **スライディングウインドウ** — 前後のターンを含めたオーバーラップchunkで文脈喪失を防止

→ **agent-memory への適用**: 現行のターン単位は悪くないが、parent-child（セッション要約 + 個別ターン）が有効。

## 3. クエリ拡張・書き換え

### 3-1. HyDE (Hypothetical Document Embeddings)

クエリからLLMで「仮想的な回答文書」を生成し、そのembeddingで検索。query-to-document類似度ではなくanswer-to-answer類似度になり精度向上[概要](https://www.emergentmind.com/topics/hypothetical-document-embeddings-hyde)。レイテンシは25-60%増加。

### 3-2. LLMベースクエリ書き換え

「前にやったあの設定」→「Claude Codeの設定ファイル変更、settings.json」のように曖昧なクエリを具体化。

→ **agent-memory への適用**: エージェント記憶検索では曖昧クエリが多いため特に有効。重要な検索（タスク開始時）ではHyDEも検討の価値あり。ただしLLM呼び出しが入るので「LLM不使用」原則とのトレードオフ。

## 4. エージェント長期記憶の学術動向

### 4-1. 主要システムの比較

| システム | メモリ構造 | 検索方式 | 特徴 |
|---------|----------|---------|------|
| **MemGPT/Letta** | Core/Recall/Archival の3層 | エージェントがツールコールで自己管理 | OS的メモリ階層[論文](https://arxiv.org/abs/2310.08560) |
| **Generative Agents** | Memory Stream + Reflection | Recency×Importance×Relevance の3軸 | LLMが重要度スコア付与[論文](https://arxiv.org/abs/2304.03442) |
| **Reflexion** | エピソード記憶バッファ | 自己反省による言語的フィードバック | HumanEval 91% pass@1[論文](https://arxiv.org/abs/2303.11366) |
| **Mem0** | ベクトル + グラフ | 自動抽出→ADD/UPDATE/DELETE/NOOP | OpenAI比+26%精度[論文](https://arxiv.org/abs/2504.19413) |
| **Zep/Graphiti** | 時間的知識グラフ | Bi-temporal model（事実の有効期間追跡） | Mem0比+18.5%精度[論文](https://arxiv.org/abs/2501.13956) |

### 4-2. Generative Agents の検索スコア（Stanford）

agent-memory の現行スコア計算と最も近い設計:

```
score = α × recency + β × importance + γ × relevance
```

- **Recency** = 指数関数的減衰（≒ 時間減衰）
- **Importance** = LLMが各記憶に1-10で付与（**agent-memoryにはない**）
- **Relevance** = コサイン類似度（≒ ベクトル検索）

→ **重要な示唆**: Importanceスコアの欠如が、agent-memoryの最大の改善余地かもしれない。

### 4-3. A-Mem: Zettelkasten方式（NeurIPS 2025）

新しい記憶追加時に自動的にリンク生成・既存メモリの進化が発生。構造化属性（コンテキスト説明、キーワード、タグ）を自動生成し、メモリ間の高次パターンを発見[論文](https://arxiv.org/abs/2502.12110)。

### 4-4. 2025-2026年の主要トレンド

**メモリ操作のRL最適化**（AgeMem）: エージェント自身がいつ何を記憶・忘却するかを強化学習で最適化[論文](https://arxiv.org/abs/2601.01885)。

**忘却の正当化**: 「忘却はバグではなく機能」。選択的忘却ポリシーの研究が活発化。dual-buffer consolidation（新しい記憶をホットバッファで猶予期間→品質チェック後に長期記憶に昇格）[サーベイ](https://arxiv.org/html/2603.07670v1)。

**Multi-Layered Memory（MLMF）**: Working Memory / Episodic Memory / Semantic Memory の3層。LOCOMOベンチマークで既存手法を上回る[論文](https://arxiv.org/html/2603.29194)。

**評価の高度化**（MemoryArena）: 受動的想起ベンチマークでほぼ満点のモデルが、実タスクでは40-60%まで性能低下することを発見。

## 6. agent-memory への改善提案（優先度付き）

### Tier 1: 高ROI・低コスト

| 改善 | 内容 | 期待効果 | 実装コスト |
|------|------|---------|-----------|
| **Cross-encoder reranker** | RRF後に日本語rerankerで上位N件を再ランク | 精度+10-15% | 低（Pythonレイヤー追加） |
| **重要度スコア** | Generative Agents方式。保存時にチャンクの重要度(1-10)をルールベースで推定（会話の長さ、質問の具体性等） | 重要な議論が埋もれない | 低 |
| **凸結合フュージョン** | RRF → `α×fts + (1-α)×vec` に変更、αはチューナブル | NDCG向上 | 低（定数1つ追加） |

### Tier 2: 中ROI・中コスト

| 改善 | 内容 | 期待効果 | 実装コスト |
|------|------|---------|-----------|
| **メタデータ拡充** | タスクタイプタグ（設定変更/バグ修正/リファクタ等）、エンティティ抽出（ファイルパス、パッケージ名） | フィルタリング精度向上 | 中 |
| **Parent-child chunking** | セッション要約（parent）+ 個別ターン（child）の2層 | コンテキスト喪失防止 | 中 |
| **アクセス頻度重み** | 頻繁に検索される記憶は減衰を遅らせる | 有用な記憶の維持 | 低〜中 |

### Tier 3: 高ROI・高コスト（将来的）

| 改善 | 内容 | 期待効果 | 実装コスト |
|------|------|---------|-----------|
| **3階層メモリ統合** | L0(Raw) → L1(Episode要約) → L2(Semantic知識) | 長期スケーラビリティ | 高 |
| **LLMクエリ書き換え** | 曖昧クエリを具体化してから検索 | 曖昧クエリの大幅改善 | 中（LLM呼び出しが入る） |
| **時間的知識グラフ** | Zep/Graphiti方式で事実の有効期間を追跡 | 時間推論の精度 | 高 |
| **選択的忘却** | 低重要度×低アクセスの記憶を段階的に圧縮→アーカイブ | ノイズ削減 | 高 |

### 現行システムの最大の改善余地

1. **Reranking がない** — RRF後の精度を底上げする最も直接的な手段
2. **重要度スコアがない** — 全チャンクが等価に扱われ、重要な議論が埋もれる
3. **メモリが追記のみ** — 統合・忘却の仕組みがなく、データが増えるほどノイズが増加
